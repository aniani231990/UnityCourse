# AI-Assisted Learning Guide: How to Learn Programming with Qwen/Claude

**Ключевой принцип:** AI - это не Google (для быстрых ответов), а **личный ментор** (для глубокого обучения)

---

## Mindset: AI как ментор, не как костыль

### ❌ WRONG Way (AI as Google):
```
User: "Как сделать ObjectPool в Unity?"
AI: [дает готовый код]
User: [копирует код]
Result: Код работает, но вы ничему не научились
```

### ✅ RIGHT Way (AI as Mentor):
```
User: "Qwen, объясни мне ObjectPool паттерн:
- Какую проблему он решает?
- Как работает внутри?
- Дай мне задачку для практики и проверяй мое решение"

AI: [объясняет концепцию]
AI: [дает задачку]
User: [пишет код сам]
AI: [проверяет, дает feedback]
AI: "А что случится, если pool пустой? Подумай и ответь"
User: [думает, отвечает]
AI: [подтверждает или поправляет]

Result: Вы ПОНИМАЕТЕ паттерн и можете применять его самостоятельно
```

## Цикл обучения с AI (Feynman + Socratic Method)

### Phase 1: Получить объяснение (AI → You)

**Prompt template:**
```
"Qwen, объясни мне [TOPIC] для Unity разработки.

Хочу понять:
1. Какую проблему решает?
2. Как это работает (концептуально)?
3. Покажи simple example
4. Покажи real-world пример из игр
5. Когда использовать, когда НЕТ (trade-offs)?

Объясняй пошагово, проверяй понимание после каждого шага."
```

**Пример:**
```
"Qwen, объясни мне Delegates в C#.

Хочу понять:
1. Что такое delegate и зачем он нужен?
2. Как он работает (это указатель на метод?)
3. Простой пример: передать функцию как параметр
4. Real-world: как Unity использует delegates для UI events?
5. Когда delegate, когда Action, когда Event?

Объясняй пошагово, я буду задавать вопросы по ходу."
```

**AI Response Tips:**
- Если непонятно - **переспрашивайте!**
- Просите аналогии: "Объясни как 5-летнему ребенку"
- Просите visual: "Нарисуй схему" (AI может описать схему текстом)

---

### Phase 2: Практика с проверкой (You → AI)

**Prompt template:**
```
"Qwen, дай мне задачку на [TOPIC]:
- Уровень сложности: [easy/medium/hard]
- Требования: [описание задачи]

Я буду писать код, а ты:
1. Проверяй правильность
2. Задавай вопросы на понимание
3. Указывай на ошибки и объясняй, ПОЧЕМУ это ошибка
4. Не давай готовое решение сразу, подсказывай направление

После того как сделаю правильно - дай более сложную задачку."
```

**Пример:**
```
"Qwen, дай мне задачку на Delegates:

Задача (средний уровень):
Создай EventBus, который может:
- Subscribe<T>(Action<T> handler)
- Unsubscribe<T>(Action<T> handler)
- Publish<T>(T eventData)

Я буду писать код по частям. После каждого метода:
- Проверяй правильность
- Задавай вопрос: 'А что если...?'
- Если ошибка - дай подсказку, но НЕ готовое решение

Начну с Subscribe метода."
```

**Как AI должен проверять:**
```
User: [пишет код]

AI: "Хорошее начало! Но подумай:
- Что случится, если вызвать Subscribe для уже подписанного handler?
- Как ты хранишь handlers внутри? Почему выбрал именно эту структуру данных?
- Что произойдет, если handler выбросит exception?"

User: [отвечает на вопросы]

AI: [подтверждает или дает подсказку]
```

### Phase 3: Объясни обратно (You → AI, Feynman Technique)

**Prompt template:**
```
"Qwen, сейчас я объясню тебе [TOPIC] своими словами.
Если я что-то понял неправильно или упустил важное - поправь меня.

[Ваше объяснение концепции]

Задай мне 3-5 вопросов, чтобы проверить глубину понимания."
```

**Пример:**
```
"Qwen, объясню тебе Delegates:

Delegate - это как переменная, которая хранит метод.
Ты можешь передать метод как параметр другому методу.
Action - это готовый delegate для методов без return.
Event - это delegate, но его могут вызывать только внутри класса.

Правильно ли я понял? Задай мне вопросы на проверку."

---

AI: "Хорошее базовое понимание! Уточняю:

1. Ты сказал 'как переменная' - а в чем отличие delegate от обычной переменной int или string?
2. 'Action для методов без return' - а если метод возвращает результат?
3. 'Event могут вызывать только внутри класса' - а подписываться можно извне?

Ответь на эти вопросы."
```

**Почему это важно:**
- Если вы можете объяснить - значит поняли
- Если не можете - AI покажет, где пробел
- Этот метод используют в Feynman Technique (техника Фейнмана)

```
"
```

```

[код]

Дай подробный feedback: что хорошо, что можно улучшить."
```

## Socratic Method: AI задает вопросы

**Prompt для AI:**
```
"Qwen, используй Socratic Method для проверки моего понимания [TOPIC].

Задавай вопросы:
- 'Почему ты выбрал такой подход?'
- 'Что случится, если...?'
- 'Как это связано с...?'
- 'Можешь привести пример, где это НЕ сработает?'

Не давай готовые ответы. Подсказывай направление, если я застрял."
```

**Пример диалога:**
```
User: "Я создал EventBus через Dictionary<Type, List<Delegate>>"

AI: "Хороший выбор! А почему Dictionary, а не List?"

User: "Потому что нужно быстро находить handlers по типу события"

AI: "Правильно. А что если один handler подписался дважды?"

User: "Хм... тогда он вызовется дважды. Это плохо?"

AI: "Подумай: хочешь ли ты, чтобы UI обновился дважды на одно событие?"

User: "Нет! Нужно проверять, не подписан ли уже"

AI: "Отлично! Как ты это проверишь? Покажи код"
```

## Levels of Understanding (проверка глубины)

AI должен проверять понимание на разных уровнях:

### Level 1: Remember (знание)
"Что такое delegate?"

### Level 2: Understand (понимание)
"Объясни своими словами, как работает delegate"

### Level 3: Apply (применение)
"Создай EventBus используя delegates"

### Level 4: Analyze (анализ)
"Сравни delegate, Action, Event - когда что использовать?"

### Level 5: Evaluate (оценка)
"Какие проблемы могут возникнуть с EventBus? Как их решить?"

### Level 6: Create (создание)
"Спроектируй систему событий для multiplayer игры"

**Prompt для AI:**
```
"Qwen, проверь мое понимание [TOPIC] на всех уровнях Bloom's Taxonomy:
1. Remember
2. Understand
3. Apply
4. Analyze
5. Evaluate
6. Create

Задавай вопросы от простого к сложному."
```

## Debugging с AI

### ❌ WRONG:
```
User: "Почему мой код не работает? [код]"
AI: "Вот исправленный код: [решение]"
User: [копирует]
```

### ✅ RIGHT:
```
User: "У меня NullReferenceException в строке 42. Вот код: [код]
Я думаю, проблема в том, что... [ваша гипотеза]
Правильно ли я понял?"

AI: "Хорошая гипотеза! Давай проверим:
1. Что происходит ДО строки 42?
2. Какое значение имеет [переменная]?
3. Что ты ожидаешь vs что получаешь?"

User: [отвечает на вопросы]

AI: "Теперь видишь проблему? Попробуй исправить сам"

User: [исправляет]

AI: "Отлично! А как можно предотвратить это в будущем?"
```

**Debugging Prompt:**
```
"Qwen, помоги мне отладить проблему:

Проблема: [описание бага]
Код: [код]
Что я уже пробовал: [ваши попытки]
Моя гипотеза: [что вы думаете]

Не давай готовое решение. Задавай вопросы, помоги найти проблему самому."
```

## Common Mistakes (как НЕ учиться с AI)

### ❌ Mistake 1: Copy-Paste Learning
```
User: "Дай код для [FEATURE]"
AI: [код]
User: [копирует]
```
**Почему плохо:** Вы ничему не научились. Завтра не сможете сделать это сами.

**Правильно:**
```
User: "Объясни, как реализовать [FEATURE]. Дай мне задачу, я сам напишу код."
```

---

### ❌ Mistake 2: Пассивное чтение
```
User: "Расскажи про SOLID принципы"
AI: [длинное объяснение]
User: "Ок, понял" [не понял]
```
**Почему плохо:** Иллюзия понимания. Вы прочитали, но не усвоили.

**Правильно:**
```
User: "Расскажи про SOLID. После каждого принципа буду объяснять обратно своими словами."
AI: [объясняет Single Responsibility]
User: "Если я правильно понял, это значит... [объяснение]"
AI: [проверяет понимание]
```

---

### ❌ Mistake 3: Нет практики
```
User: "Объясни все паттерны проектирования"
AI: [объясняет 20 паттернов]
User: "Круто!" [не применял ни одного]
```
**Почему плохо:** Теория без практики = забудете через неделю.

**Правильно:**
```
User: "Объясни Observer паттерн. Потом дай задачку на практику. Потом следующий паттерн."
```

---

### ❌ Mistake 4: Боязнь спросить "глупый" вопрос
```
User: [не понял, но молчит]
AI: "Всё понятно?"
User: "Да" [нет]
```
**Почему плохо:** Пробелы в знаниях накапливаются.

**Правильно:**
```
User: "Я не понял эту часть. Объясни проще / покажи пример / нарисуй схему"
```

## Advanced: AI as Pair Programming Partner

**Prompt:**
```
"Qwen, давай сделаем pair programming:

Я создаю [PROJECT].
Я буду писать код по частям, а ты:
- Задавай вопросы о моих решениях
- Предлагай альтернативы
- Указывай на потенциальные проблемы
- Хвали хорошие решения (и объясняй, почему хорошо)

Начнем с проектирования архитектуры."
```

**Example Session:**
```
User: "Создаю Inventory System. Начну с класса Inventory."

AI: "Хорошо! Перед кодингом:
- Какие операции должен поддерживать Inventory?
- Mutable или immutable?
- Как будешь хранить items?"

User: "Хм, не подумал. Наверное immutable, чтобы легче тестировать"

AI: "Отличное решение! Если immutable, какую структуру данных используешь?"

User: "ImmutableList<Item>"

AI: "Хорошо. Теперь покажи сигнатуру метода AddItem"

User: "Inventory AddItem(Inventory current, Item item)"

AI: "Правильно! Метод чистый, возвращает новый Inventory. А что если inventory full?"

User: "Вернуть Result<Inventory> вместо просто Inventory?"

AI: "Exactly! Теперь пиши код, я буду проверять."
```

## Final Tips

1. **Будьте активным студентом**
   - Задавайте вопросы
   - Объясняйте обратно
   - Пишите код сами

2. **AI - инструмент, не костыль**
   - Используйте для обучения, не для копирования
   - Понимание > Working Code

3. **Практика > Теория**
   - 80% времени - coding
   - 20% времени - reading

4. **Build Projects**
   - Tutorial Hell - ловушка
   - Создавайте свои проекты с нуля

5. **Review, Review, Review**
   - Повторение через промежутки времени
   - День 1, День 3, День 7, День 30
